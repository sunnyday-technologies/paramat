Designed around the assembled demo—not a generic ESP32 case

The 44-pin YD/AITRIP controller plugs into its green terminal adapter, so clipping the ESP32 PCB itself would obstruct the header rows. The current first-fit model mounts the adapter through four board holes. Short M2.5 screws form a light thread in blind plastic pilot slots; no nuts or heat-set inserts are required for stationary bench use.

Measure before the full print: the current 72.5 × 32 mm hole pattern comes from a published reference adapter. The actual AITRIP board's two center-to-center dimensions and hole diameter still need to be confirmed.

Print → fit → prove

1

Calibrate cheaply

Measure the adapter-hole pattern, then print both coupons in the intended material. Choose the screw pilot that is snug without splitting and confirm the PN532 clip force.

2

Assemble openly

Print the flat carrier in PETG, mount the adapter with four M2.5 × 6 mm screws, then install the controller and PN532. Use a brim if the long corners begin lifting.

3

Test the real system

Connect both USB-C cables and intended wires. Verify NFC read/write with Wi-Fi active and at the final location beside the printer.

What the computer proved—and what it did not

Completed: the CAD generator produced valid solids. Five automated checks cover declared board envelopes, reference mounting inputs, board separation, and a nominal 145.7 × 78.0 mm footprint within a 180 × 180 mm plate envelope.
  • Actual adapter hole pitch is measured
  • Adapter seats on all four bosses
  • Four screws start without splitting
  • PN532 clips without visible stress
  • Both USB-C plugs fit together
  • Used terminals and BOOT/RST are reachable
  • NFC works with ESP32 off, on, and Wi-Fi active
  • Range remains reliable beside the A1 mini
Still pending: actual adapter-hole measurements, physical fit, connector access, and RF validation. Until the real print passes the checklist, this remains a first-fit prototype—not a claim that every reseller batch will fit.

Compatibility boundary

This is a mechanical carrier for an external PN532/ESP32 reader. It does not make a stock Bambu AMS Lite understand an NFC standard by itself. The current ParaMat browser writer creates OpenSpool 1.0 JSON on compatible tags; the bridge then maps supported data toward the printer. OpenTag3D is a separate encoding, and no native Bambu compatibility is claimed here.

The external OpenSpool Mini enclosure targets different controller hardware and is not redistributed here. This model is new CadQuery geometry derived from published board envelopes and mounting dimensions.

Design method

Published dimensions established the first geometry; the product photograph resolved orientation and access; RF constraints kept the antenna open; parametric CAD preserved revision speed; and automated checks rejected obvious plate, spacing, and envelope errors. The physical print now supplies the evidence that a screen cannot: actual shrinkage, clip force, connector reach, and read range.
